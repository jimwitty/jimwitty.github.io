> 整理自 2026-10-29 对话问答。主题一句话：x86 的历史就是“物理墙不断撞上来、兼容包袱不断往上摞”——每一代新机制都是被上一代的物理限制逼出来的，而每一次“临时兼容方案”都会在系统里躺几十年。

---

## 1. 保护模式怎么来的

8086（1978）只有实模式：段:偏移合成 20 位地址，1MB 内存，没有任何保护——任何程序可以改任何内存，操作系统和应用程序一视同仁。多任务操作系统（OS/2、Unix 移植）想要两件事：一是突破 1MB，二是程序之间不能互相踩。80286（1982）的回答就是保护模式：段不再是一个数，而是一个“描述符”——基址 + 界限 + 访问权限，另加 0～3 四个特权环（Ring）。每次访存硬件先查界限、查权限，过不了就异常。这就是“保护”二字的来源：保护 = 界限检查 + 特权检查。

286 的保护模式有个著名残疾：进得去出不来——设计上没有回实模式的路，只能复位 CPU。OS/2 为了切回实模式跑 DOS 程序，真用过“让键盘控制器发复位脉冲”和“三重故障故意崩一下”这种野路子。80386（1985）补上三件大事：32 位、分页（页表才是后来真正赢的机制，段被压成平坦模型基本弃用）、虚拟 8086 模式（在保护模式里圈出一块地假装实模式，286 的残疾治好了）。

## 2. A20 地址线怎么来的——x86 第一兼容笑话

8086 地址总线 20 根线（A0～A19），段:偏移最大能算出 0x10FFEF，超过 1MB 的部分因为没有第 21 根线，直接回绕到低地址。有些程序（包括 DOS 的一些用法）依赖这个回绕。

286 有 24 根地址线，不回绕了，依赖回绕的程序当场出错。IBM 在 PC/AT（1984）上的解法：在第 21 根线（A20）上串一个可控的门——关门时强制 A20 = 0，人工模拟回绕；开门时 286 才能摸到 1MB 以上的内存。更荒诞的是这个门的开关：借了 8042 键盘控制器的一根空闲输出脚。于是几十年里，x86 启动代码都要去和键盘控制器“借”一条地址线——WRK 第 1 批 AP 启动链里“A20 前提（BIOS 已开）”就是它的出处。后来有了 0x92 端口的快速 A20，又后来 Pentium 干脆在 CPU 上留了 #A20M 引脚让芯片组在内部屏蔽。DOS 年代 HIMEM.SYS 管 A20 是为了进 HMA（1MB 之上那 64KB，只有开 A20 才够得到，DOS=HIGH 就把 DOS 本体塞那儿）。到 UEFI 年代 A20 基本是化石：多数现代平台默认常开，但这套开关在芯片组里躺了很多年才退场。

## 3. CR 寄存器如何诞生

模式切换需要一个地方放“CPU 全局状态”：现在是不是保护模式、分页开没开、页目录在哪——这些不属于任何通用寄存器，也不该被普通指令随手改。286 先有了 MSW（机器状态字），里面一位 PE 就是保护模式开关。386 把它正式扩成 CR 组：CR0 = MSW 的成年版（PE、PG 等开关），CR2 = 缺页时存出错的线性地址，CR3 = 页目录基址，CR1 保留——CR1 不是接口，是 MOV CR 编码编号空间里留的洞，内核态碰它得 #UD。CR4 是 Pentium 才加的（一堆新特性的开关：PSE 大页、PAE 等）。CR8 是 x86-64 才加的，就是 TPR——第 8 批讲的“抬 IRQL = 写 CR8”，几十年后控制寄存器家族还在长个。

## 4. 一级、二级缓存怎么来的

最初没有缓存：早期 CPU 和内存速度相当，访存不用等。之后 CPU 频率狂飙，DRAM 延迟几乎原地踏步，“内存墙”出现——CPU 取个数要等几十上百个周期。救法是拿 SRAM（快、贵、占地大）做小仓库垫在 CPU 和 DRAM 之间，靠局部性原理（刚用过的大概率再用、附近的大概率也要用）把命中率做上去。

分级的诞生顺序很说明问题：386 时代缓存是主板上的外置芯片，那是后来的“L2 的祖宗”；486（1989）第一次把 8KB 缓存塞进 CPU 芯片内，这才有了 L1 的概念——离核心最近、最小、最快；Pentium 把 L1 拆成指令/数据两块（哈佛式，避免取指和访存打架）。L2 的位置一路往核心爬：主板 → Pentium Pro 的同封装 → Pentium II 的卡匣（半速）→ Pentium III 后期 on-die 全速。多核时代又加了 L3 做全核共享。一句话：**层级 = 速度、容量、成本三者的折中阶梯**，越靠近核心越快越小。附带的新问题是缓存一致性——多个缓存各存一份同一地址，靠 MESI 这类协议对账（自旋锁机理里 MESI 的由来）；DMA 也得刷缓存（第 9 批 KeFlushIoBuffers 的根）。

## 5. 多核解决了什么、带来了什么

为什么不多提主频？2004 年前后 Dennard 缩放失效：频率再往上提必须加电压，功耗按电压平方涨，Pentium 4 撞上约 4GHz 的功耗墙，Tejas 计划被砍，Intel 转向“用核数换频率”——加上单核的流水线加宽加深收益也已递减（ILP 墙）。中间过渡是超线程（2002，Pentium 4 HT）：一个核伪装成两个逻辑核，填流水线气泡。

多核解决的是吞吐和每瓦性能：并行负载（服务器、多任务、编译、渲染）近乎线性受益。但新问题一串：缓存一致性流量随核数涨，监听式协议撑不住，大核数改目录式；NUMA 出现——内存离哪个核近成了性能问题（WRK 里 KeNumaInitialize 就是为这个）；内存一致性模型、锁竞争（SYNCH_LEVEL 本质是多核锁级别设计）、伪共享、调度均衡；暗硅（晶体管多到不能同时全开）；还有安全侧的共享缓存侧信道和 SMT 争用，Spectre 那一代问题在多核/SMT 环境里更难收拾。单核时代的问题是“怎么让一个线程跑得快”，多核时代的问题变成“怎么让一群线程别互相拖死”。

## 6. ISA 是什么、只有这一种吗

ISA（工业标准架构）是 IBM PC 的总线：1981 年原版 8 位、62 脚、4.77MHz；1984 年 PC/AT 加了延长段，变 16 位数据、24 位地址——第 9 批学的 ISA DMA 24 位限制就来自给 ISA 配的 8237 DMA 控制器。ISA 的性格：慢（约 8MHz）、配置靠跳线和拨码开关（IRQ 还不能共享，声卡网卡抢 IRQ 是装机噩梦）、没有配置空间的概念。第 10 批的 PnP 在 ISA 上只能打补丁（ISA PnP 是 retrofit），根源就在这儿。

之后是一部总线战争：IBM 想收权推专有的 MCA（1987），惹出九大厂商联合的 EISA（1988）；VLB（1992）是 486 时代把总线直连 CPU 的短命 hack；真正的胜者是 Intel 的 PCI（1992）——有标准配置空间（第 9 批配置空间访问的出处）、支持总线主控、线中断可电平触发共享，PnP 才算原生可行；显卡专用走 AGP（1997）；2004 年 PCIe 把并行共享总线整个换掉：串行、点对点、分组交换——名叫总线，其实已经不是总线了，第 8 批的 MSI/MSI-X 正是 PCIe 这种“消息”本质的产物。再往里，FSB 前端总线被内存控制器进 CPU（AMD K8 2003、Intel Nehalem 2008）取代，核间互联变成 QPI/UPI、Infinity Fabric 这类片上网络。

## 7. 64 位长模式怎么来的

**为什么需要它**：32 位的墙首先是地址——每进程虚拟空间 4GB，服务器和数据库先撞上。Intel 的止痛药是 PAE（Pentium Pro，1995）：物理地址扩到 36 位（64GB），但每进程虚拟空间仍是 4GB，还要靠 AWE 这类窗口 API 换页用，治标不治本。其次是寄存器太少：x86 只有 8 个通用寄存器，编译器被迫频繁倒腾内存；x87 浮点栈也早已老旧。

**谁做的，又是兼容胜出**：Intel 当时的路线是推倒重来——IA-64（Itanium，2001），全新架构、不兼容 x86，结果商业失败。AMD 反其道行之：1999 年公布 x86-64 规范，在保护模式骨架上扩位，2003 年 Opteron/Athlon 64 落地，老程序原样能跑。Intel 被迫跟进（EM64T，2004）。和 A20、PCI 的故事同一主题：**在 x86 世界里，兼容路线永远战胜干净路线**。

**长模式是什么**：它是保护模式的一个新状态（IA-32e），内含两个子模式：64 位模式与兼容模式（跑 32 位程序）。进入链就是 WRK 第 1 批 AP 启动里见过的那串：先在保护模式下开 PAE（CR4.PAE）→ 装 CR3 → 置 EFER.LME → 开分页（CR0.PG）即进入长模式但仍是兼容子模式 → 远跳到 64 位代码段，才真正落进 64 位模式。注意它不是新开一个模式，而是“分页一开、描述符一换”地从保护模式里长出来的。

**它改了什么**：

- **寄存器**：通用寄存器 8 → 16 个（RAX～R15），宽度全变 64 位；新增 RIP 相对寻址，位置无关代码不再需要占一个寄存器当基址。
- **地址与页表**：虚拟地址先行实现 48 位（256TB），页表从 PAE 的三级变四级（新加 PML4 一层）；后来又有五级页表（57 位）。地址必须是“规范形”：高位全是符号扩展，中间是洞，非规范地址访问直接 #GP——用户空间占低半、内核占高半的布局由此而来。
- **段正式退休**：CS/DS/ES/SS 的基址在 64 位模式被强制为 0、界限不查，286 发明的段机制在它自己的后代手里寿终正寝；只剩 FS/GS 保留可设基址，专供线程局部存储与内核的处理器控制区（WRK 里 GS/PCR 的用法、swapgs 指令就是这条尾巴）。分页完成了对段的最终替代。
- **进内核的正路换代**：syscall/sysret 成为 64 位系统调用入口（SYSENTER 的后继）；PAE 页表项第 63 位的 NX（不可执行）随这个时代普及成 DEP，数据页不能再当代码跑——这是安全线的一件大事。
- **兼容的边界**：32 位用户程序在兼容子模式里跑（用户态有 WOW64），但 32 位驱动不许进 64 位内核——WRK 第 1 批的结论“用户态有 WOW64，内核态没有”就是这条边界。

**代价**：指针全变 8 字节，内存占用与缓存压力上升；数据模型分歧（Windows 用 LLP64，long 仍 32 位；Linux 用 LP64）成了移植坑；页表多一级（五级再多一级），TLB 未命中时的页表漫游更长。长模式没有消除历史，它只是又一次证明：在 x86 上，进化永远是嫁接，不是重生。

## 收束

这七问共享一个主题：**每一代新机制都是被上一代的物理限制逼出来的，而每一次“临时兼容方案”（A20 门、286 复位回实模式、ISA 跳线、PAE 止痛药）都会在系统里躺几十年**。这也是在 WRK 源码和驱动批次里反复撞见“历史因素与兼容考虑”的总根源。

## 附：追问补记——NUMA：内存离哪个核近为什么成了性能问题（2026-10-29）

- **旧世界（UMA）**：单核与早期 SMP 时代，内存控制器在北桥里，全机一个，内存条都挂在它下面。所有核到所有内存的路径一样长、一样慢，访问时间均匀（Uniform Memory Access）——“内存”是一个公共池，不存在远近。
- **分水岭**：内存控制器进 CPU——AMD K8（2003）先行，Intel Nehalem（2008）跟进。从此每个 CPU 座（socket）自带控制器、自带一批内存条，拓扑变成：每座一份“本地内存”（自家控制器直连）+ 其余座的“远程内存”（要过 QPI/UPI/Infinity Fabric 片间互联、再进对方控制器）。NUMA（Non-Uniform Memory Access，非均匀内存访问）由此进入 x86 主流；WRK 里的 KeNumaInitialize 就是系统启动时枚举这套节点拓扑。
- **差距在哪**：① 延迟：远程访问多跳一程互联加一个控制器，延迟约为本地的 1.5 倍上下；② 带宽：互联带宽小于本地内存通道带宽，且全座的跨座流量共享它，多核齐轰远程内存会把互联打满、排队；③ 一致性流量同路：MESI 的跨座对账也走互联，一条热锁的缓存行在两座之间弹跳时，每次拿锁都付远程延迟（与自旋锁/SYNCH_LEVEL 的多核代价同根）。
- **软件为什么背锅**：页的“家”由首次触碰决定（first-touch：哪个节点的线程先碰这页，物理页就分在哪个节点）。若线程随后迁到别的节点、或数据由别的节点的线程消费，就变成全程远程访问。所以 OS 要 NUMA 感知调度与分配（线程尽量不离它的节点），大应用要按节点切分数据。
- **缓存是缓冲层**：热点数据会被缓存搬到用它的核旁边，所以 NUMA 问题集中在缓存装不下的工作集上——工作集全在缓存里时远近不显形，溢出到 DRAM 时延迟差全额兑现。
- **现在更细**：单座内也 NUMA——AMD EPYC 的 chiplet 设计（多芯粒、每芯粒本地内存通道，NPS 可把一座切成多个节点）、Intel 的 SNC（子 NUMA 集群）。小天的宿主正是 AMD EPYC，这台机器的拓扑本身就是 NUMA 教材。

## 附：追问补记——本地/远程是路径长短，不是访问权限（2026-10-29）

- **先纠正**：本地/远程不是“能不能访问”的区别。每个 CPU 都能访问全部物理内存，代码不用改、不用申请。区别只有路径长短与代价。
- **用 4G + 4 座走一遍**：4G 内存按段挂在四个座的控制器下（如 0~1G 归 A 的控制器、1~2G 归 B 的控制器，依此类推），全机物理地址空间仍是一个整体的 4G。A 访问第一个 1G：请求直接进 A 自己的控制器 → DIMM → 返回，路径最短，这是“本地”。A 访问第二个 1G：A 的请求走座间互联到 B 的控制器，B 的控制器读自己 DIMM、把数据经互联送回 A，这是“远程”——多跳一程互联，延迟更高、带宽与全机跨座流量共享。
- **关键纠正**：“去找第二个 CPU 要”这句话错在对象：要找的是 B 的内存控制器（独立硬件部件），不是 B 的计算核。B 的核全程不参与、不知情，可能正忙别的程序；控制器谁的请求都接，自动路由，无许可概念。
- **first-touch 的意义回扣**：页分在哪个座的那份内存里，就决定了主要访问它的核走哪条路。线程在 A 上跑、数据分在 B 的内存里，就每次访问都多跳一程——NUMA 性能问题就是这么来的，不是被“锁”在本地出不去。

## 附：追问补记——NUMA 措辞两处磨精确（2026-10-29）

- **管理者是内存控制器，不是 CPU 核**：地址空间确实按段对应到不同座，但每段的“管理者”是该座的内存控制器（硬件部件，负责接请求、读 DIMM、送数据）；核是使用者，不管理任何段。
- **“向其它 CPU 要数据”磨成**：向对方座的内存控制器发请求。读是把数据取回来，写是把数据送过去存，双向都走同一条互联路径；对方核不参与。哪段地址归哪个控制器，由开机时硬件地址映射定死（DIMM 挂在哪个控制器下决定的），OS 只是开机时学到这张图（KeNumaInitialize 枚举）；OS 能决定的是“新页从哪个座的池子里分”（first-touch），改不了路由图本身。

## 附：追问补记——DIMM 是什么；内存控制器为什么必须拆分（2026-10-29）

- **DIMM**（Dual Inline Memory Module，双列直插内存模块）：就是内存条——一块插在主板内存槽里的小电路板，上面焊着多颗 DRAM 芯片（颗粒），数据本体就存在这些颗粒里。做成可插拔条状是为了标准化、可扩容、可更换。归属链：DIMM 插在哪个槽 → 槽经主板走线连到哪个内存控制器的哪条通道（控制器与 DIMM 之间的独立信号线，一条通道独立传数据，多通道并行加带宽）→ 那个控制器在哪个座里 → 这条 DIMM 的地址段就归那个座本地。内存控制器不存数据，它是调度与翻译：把请求翻成 DRAM 的行列访问时序，数据进出的是颗粒。
- **为什么拆分（结论先行）**：不是想拆，是“统一一个”在大规模下先堵死。拆分是改革目的，NUMA 只是副作用。
- **原因一：带宽要靠加法**。一个控制器的总带宽 = 通道数 × 通道速率，而通道数受 CPU 引脚数与芯片面积限制，单控制器撑死十来条通道。多核一起访存的总需求随核数涨，很快超过单控制器上限——所有人排队等一个控制器，延迟爆炸。每座放一个控制器，加一座就多一份带宽，总带宽随座数线性增长。
- **原因二：信号物理**。内存通道是高速并行信号：一条通道挂的 DIMM 越多信号越差，控制器离 DIMM 越远频率越上不去。控制器必须贴着它管的 DIMM——放进座内、挨着本座插槽，是电气规律逼的；统一控制器意味着一半 DIMM 要经长走线连到远方，高频下信号完整性直接烂掉。
- **原因三：共享必经点必成瓶颈**。历史上共享前端总线 + 单北桥的 UMA 架构正是这样被淘汰的：总线和北桥是全机访存的必经之路，核一多就堵死。K8/Nehalem 的改革（控制器进 CPU + 点对点互联）就是拆瓶颈；本地延迟与总带宽都改善，代价才是跨座的非均匀性。
- **公平边界**：小规模下统一确实更省事——单座机器根本没有 NUMA 问题（所有内存都是本地的）。这是规模问题：规模小统一最优；规模大统一做不到，只能拆，再靠 OS 的 NUMA 感知把大部分访问留在本地，让拆分的代价只在跨座时才付。
