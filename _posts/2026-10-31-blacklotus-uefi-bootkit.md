> 本文由对话答疑整理而成：BlackLotus（2022 年论坛售卖、2023 年 3 月 ESET 证实）是第一个能在打满补丁的 Windows 11 上绕过 Secure Boot 的 UEFI bootkit。本文拆它的五步攻击链——部署带洞但签名合法的微软引导组件（CVE-2022-21894 Baton Drop）、引导期任意代码执行、把自签证书登记进 MOK 混进验签体系内部、接管 Windows 加载链、放下带 ESP 文件自保护的内核 rootkit，并讲清微软的吊销困局。与《LoJax 讲透》《UEFI 讲透》互为姊妹篇。

---

BlackLotus 是把 UEFI 机制反过来用的标本：Secure Boot 的验签点、ESP 的文件化引导、NVRAM 启动项，它全用上了。按顺序讲：先分清三个名词，再拆它的完整攻击链，最后讲为什么它难删、微软为什么治它治得那么费劲。

**先分清：rootkit、bootkit、UEFI rootkit**

- **Rootkit（root 工具箱）**：一类以"隐藏自己并长期驻留"为目的的恶意代码，核心能力是让系统里的其他观察者（进程列表、文件列表、杀毒软件）看不见它。它是个功能概念，不限定住在哪一层。
- **Bootkit**：驻留点选在启动过程中的 rootkit。操作系统还没起来它就先执行，于是它能在内核加载之前修改内核、关掉防护——杀毒软件出生得比它晚，先天矮一截。
- **UEFI rootkit**：bootkit 里最深的一种，执行点在固件阶段。内部还要再分两档，这档之分是理解 BlackLotus 的关键，下面马上讲。

**BlackLotus 的出身**

BlackLotus 于 2022 年 10 月起在地下论坛公开售卖，标价 5,000 美元，卖家打的广告就是"能绕过 Secure Boot、带自有 Secure Boot 组件、能关 Defender、能防删除"。2023 年 3 月 1 日，ESET 发布完整分析（研究员 Martin Smolár），确认广告基本属实：**这是第一个被公开证实的、能在打满补丁的 Windows 11（含当时最新版吊销库）上绕过 Secure Boot 的 UEFI bootkit**。注意它的定位：安装需要先拿到目标机的管理员权限——它不是入侵的矛，是入侵成功之后扎根的钉子，属于持久化武器。

**关键澄清：它并不改主板固件**

"UEFI rootkit"容易让人以为它把自己刷进了主板 SPI Flash 芯片。BlackLotus 没有。它的前辈 LoJax（2018 年 ESET 发现，第一个野外 UEFI rootkit）才是真刷固件：利用带合法签名的驱动读写 SPI Flash，把恶意 DXE 驱动（DXE 是 UEFI 固件内部驱动分发阶段）写进固件本体，重装系统、换硬盘都杀不掉。

BlackLotus 走的是另一条路：**它住在 ESP 分区里，伪装成合法的引导文件，让固件在每次开机时"合法地"执行它**。它攻击的不是固件代码本身，而是 Secure Boot 的信任链。这条路门槛更低（不用碰因主板而异的 Flash 写入），隐蔽性稍弱（ESP 是个普通 FAT32 分区，文件躺在那里），但配上它绕 Secure Boot 的本事，实际效果对绝大多数受害者没有区别。

**攻击链：五步**

**第一步，安装器在 Windows 里落脚（需管理员权限）。**安装器先做两件准备工作：通过注册表关掉 HVCI（内存完整性，VBS 的组件——它会拦后面要加载的未签名内核驱动，所以必须先拆）和 BitLocker 相关校验（防止改动启动链触发恢复密钥锁定），然后往 ESP 写入一整套文件。

**第二步，部署"带洞但签名合法"的微软引导组件。**这是整条链的根。ESP 里放进的是微软官方签名的旧版 Windows 引导组件（bootmgfw.efi 等），它们含有一个已知漏洞 CVE-2022-21894，业内代号 **Baton Drop**（"掉棒"，指接力棒在交接时脱手——Secure Boot 的信任在这里脱手）。要害在于：**这些文件虽然有洞，但签名完全合法，且当时尚未被列入 dbx 吊销库**——dbx 是固件里的签名吊销名单（Secure Boot 四级密钥库之一），不在名单上，固件就放行。微软修了新版本，但旧版本"有洞的合法签名"在信任体系里仍然算数，这正是 Baton Drop 一类漏洞的共同命门：**吊销一个被全世界装机量依赖的引导程序，比修一个洞难得多**，这句话后面还要回来。

**第三步，利用 Baton Drop 在引导期拿到任意代码执行。**下次重启，固件验签通过（签名合法）→ 加载带洞的 bootmgfw → 漏洞触发，攻击者获得在 UEFI 引导阶段执行任意代码的能力。此刻 Secure Boot 名义上还开着，但它的判决已经被架空：执行流到了攻击者手里。

**第四步，给自己发一张永久通行证：登记 MOK。**拿到执行权后，BlackLotus 部署一套 Linux 世界常见的 shim 机制组件。先解释 **shim**：它是一个由微软签名的极小引导加载器（因为固件默认只信任微软的证书，各 Linux 发行版就用它做跳板），它除了验微软签名，还认一个额外的密钥库 **MOK（Machine Owner Key，机器属主密钥）**——设计本意是让机器主人登记自己的证书、引导自己签名的内核，是 Secure Boot 有意留的"主人后门"，有正规的管理工具和登记流程。BlackLotus 利用第三步的任意代码执行，把**攻击者自己的自签证书塞进 MOK**，再放上 shim 和由攻击者证书签名的 bootkit 本体（伪装成 grubx64.efi 的文件）。自此之后每一步都是"合法"的：固件验 shim 的微软签名 ✓ → shim 验 bootkit 的签名，证书在 MOK 里 ✓ → 放行。不再需要每次触发漏洞——通行证是持久的。这一步是 BlackLotus 设计上最阴的地方：它没有持续对抗验签，而是**混进了验签体系内部**。

**第五步，bootkit 接管操作系统加载，再放下内核 rootkit。**每次开机：固件 → shim → bootkit。它在 Windows 引导链（bootmgfw → winload → 内核）加载过程中逐段下手，修改内存中的加载器与内核映像，关掉代码完整性检查与 PatchGuard 初始化（注意分工：PatchGuard 是运行时巡查，出生之前就被摘掉开关，它连出场机会都没有——这正是攻防史上"防线下沉"之后攻击者把战场再往外推到固件层的实证）。随后加载它自带的未签名内核 rootkit 驱动，该驱动再部署用户态的 HTTP 下载器组件负责与 C2（命令与控制服务器）通信、接收后续载荷。内核组件还反过来**保护 ESP 里的 bootkit 文件**：拦截对这些文件的写入与删除，让管理员在 Windows 里看见了也删不掉——驻留点和保护者分居两层，互相守望。

**为什么难删、难防**

- **重装 Windows 不掉**：它住在 ESP，不住在系统分区；只格式化系统盘重装，它原封不动。彻底清除要连 ESP 一起重建，并更新固件的 dbx。
- **安全软件起步太晚**：Defender、EDR 都是内核起来之后才加载，而 BlackLotus 在它们出生之前已经改过内核、关过防护。事后扫描只能查到它留下的用户态组件，拔不掉根。
- **藏身地冷门**：ESP 平时不挂载盘符，日常运维和多数取证流程不看它；NVRAM 启动项里多一条 shim 也很不起眼。
- **检测要靠"量"而非"拦"**：TPM 的度量启动（Measured Boot，把每一步引导组件的哈希记进 TPM 的 PCR 寄存器，供事后审计比对）能发现引导链被换过，但它只记录不拦截，且日常极少有人去核对这本账。

**微软的治法与困局**

根治只有一条：把带 Baton Drop 的旧引导组件的签名塞进 dbx，全世界固件一起吊销。微软 2023 年 5 月发布 CVE-2023-24932 与配套的 KB5025885，做的正是这件事，但推进得异常小心，分了好几个阶段、默认不强制、留了大量手动步骤，强制吊销的时间表一再推迟。原因就是第二步埋的那句话：**那些"带洞的合法签名"同时也是无数合法系统的引导程序**——老安装盘、恢复盘、PE 维护盘、Linux 双系统介质全靠它们引导，一旦全球固件一夜吊销，海量设备会直接开不了机、进不了恢复环境。攻击者躲在装机量的肉盾后面，防守方的最强武器（吊销）就投鼠忌器。这是攻防史收束规律的又一次兑现：同级对抗拼的是成本曲线，而吊销体系里防守方的成本被整个生态的存量顶到了天上。

防御侧能做的（按性价比）：开启 Secure Boot 并保持固件与 dbx 更新；不关 HVCI（它被关本身就是强烈的入侵信号）；把 ESP 内容与 NVRAM 启动项纳入基线审计（多出 shim、grubx64.efi、陌生的 .efi 文件即告警）；对高价值机器启用 TPM 度量启动的事后比对；以及最根本的——别让攻击者先拿到管理员权限，BlackLotus 的整条链都建立在"已经进来了"这个前提上。

和前辈们并排收束：LoJax 刷固件（最深、最难清除、门槛最高），CosmicStrand、MoonBounce 同属固件植入一档；ESPecter 只改 ESP 但过不了现代 Secure Boot；BlackLotus 第一个把"不碰固件、只骗信任链"这条路走到能通杀打满补丁的系统——它证明了 Secure Boot 的薄弱点不在验签算法，而在**签名资产的生命周期管理**：一个签名发出去容易，想收回来，要问全世界装机量答不答应。
