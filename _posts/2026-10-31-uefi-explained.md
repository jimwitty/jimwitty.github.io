> 本文由对话答疑整理而成：从 BIOS 的四条原罪（16 位实模式、MBR 的 2.2TB 死线、446 字节引导代码、无安全根）讲起，看 EFI/UEFI 如何逐条还债——本地字长执行、GPT、ESP 文件化引导、驱动与协议模型、NVRAM 启动变量、Boot/Runtime 两班服务与 ExitBootServices 的一刀、Secure Boot 的安放点、胶囊更新，并交代它与 ACPI 的分工和它自身的攻击面代价。

---

这个概念正卡在 Windows 启动学习线的上游：WRK 源码里的加载链是 BIOS 时代的世界（MBR、实模式跳板、ntldr），UEFI 是把那个世界整个换掉的东西。以下从定义讲起，一路讲到为什么非换不可。

**UEFI 是什么**

UEFI 全称 Unified Extensible Firmware Interface，统一可扩展固件接口。先把性质钉死：**它是一套规范，不是一个具体软件**——规定"固件应该长什么样、提供哪些服务、操作系统怎么跟它交接"。维护者是 UEFI Forum（Intel、微软、AMD、苹果和各大固件厂商组成的联盟）。各家主板上实际运行的固件代码是按这套规范写的实现（开源参考实现叫 EDK II / TianoCore，美商 AMI、Phoenix、Insyde 的商用固件都源于它再定制）。

它站在启动链的最底层：按下电源 → CPU 从复位向量取第一条指令 → 执行固件（存在主板 SPI Flash 芯片里）→ 固件初始化 CPU、内存、总线、设备 → 找到并加载引导加载程序（如 Windows 的 bootmgfw.efi、Linux 的 GRUB）→ 引导程序加载操作系统内核 → 移交。UEFI 管的就是从上电到移交内核这一整段，附带一小撮在系统运行期继续可用的服务。

注意一个细节：UEFI 世界里的可执行文件就是 PE 格式（和 Windows 的 .exe 同一种格式，后缀 .efi），入口点签名统一，主体用 C 写。这不是巧合——它出自 Intel，设计语言就是现代的。

**为什么要有它：BIOS 的四条原罪**

要理解 UEFI，必须先看它替代的是什么。传统 BIOS（Basic Input/Output System，基本输入输出系统）源于 1975 年的 CP/M，1981 年被 IBM PC 固化成事实标准。它的接口假设停留在 1981 年：

1. **16 位实模式**。BIOS 代码是 16 位的，只能直接寻址 1MB 内存；它提供的服务靠软件中断调用（int 13h 读盘、int 10h 显示之类），调用时 CPU 必须在实模式。所以 BIOS 时代的启动链是：上电实模式 → 读 MBR → 第一段引导代码在实模式跑 → 再由引导代码自己搭跳板进保护模式、长模式。WRK 源码学习中遇到的"实模式到保护模式跳板"、A20 门那些麻烦事，根源都在这里——不是 Windows 想这么折腾，是 BIOS 只给了实模式这一个起点。

2. **MBR 分区表的硬顶**。MBR（Master Boot Record，主引导记录，磁盘第 0 扇区）里的分区表用 32 位记录扇区号，扇区 512 字节，32 位 × 512 字节 = 2.2TB——超过这个容量的硬盘在 MBR 体系里无法完整描述，更无法从其上启动；主分区还只许 4 个。2010 年前后 3TB 硬盘上市，这条直接成了死线。

3. **固件不认识文件系统，引导代码只有 446 字节**。MBR 扇区 512 字节里，446 字节是代码、64 字节是分区表、2 字节是签名。固件能做的只是"把第 0 扇区读进内存 0x7C00 处然后跳过去"，真正的找文件、读内核全靠这 446 字节起步层层接力（这就是 ntldr 之前那串跳板的由来）。同时固件里没有驱动模型：显卡、网卡、RAID 卡想在启动期工作，靠各自插一块 Option ROM（卡上自带的 16 位代码芯片），无标准、无签名、无管理。

4. **没有任何安全根**。谁的扇区代码都能引导，启动期无法验签——bootkit（在操作系统加载前驻留的恶意代码）在 BIOS 世界里如入无人之境，因为压根没有"验"这个动作。等到微软想做 Secure Boot（安全启动，启动链逐级验签），发现 BIOS 接口里根本没有安放验签环节的位置。

一句话收束：BIOS 的天花板是"16 位实模式 + 按扇区寻址"。64 位 CPU、TB 级硬盘、PCIe 设备、网络启动、启动链验签，每一样都在顶这块天花板。修修补补（比如 int 13h 扩展）救不了，因为病根在接口假设本身。

**转世：EFI 的由来**

直接导火索很具体：90 年代末 Intel 做 Itanium（IA-64 架构）时发现，**Itanium 根本没有 16 位实模式**，BIOS 那套代码在它上面一行都跑不了。Intel 只得从零设计新固件接口，1999–2000 年推出 EFI 1.0。2005 年 Intel 把规范交给新成立的 UEFI Forum，改名 UEFI，推广到 x86。普及的临门一脚是 2011 年后：大硬盘逼着用 GPT，Windows 8 把 Secure Boot 设为认证要求，UEFI 成为 PC 出厂标配。Windows 侧的支持线：Vista SP1 x64 起可从 UEFI 启动，Win7 x64 完善，Win8 起 Secure Boot 落地。

**UEFI 是怎么逐条还债的**

- **本地字长执行**：固件本身是 64 位（或 32 位）C 代码编译成的 PE 文件。启动链从第一步起就在保护/长模式，不需要实模式跳板；引导程序拿到的已是 64 位 flat 内存模型。
- **GPT 分区表**：GPT（GUID Partition Table，GUID 分区表）用 64 位 LBA（逻辑块地址），寻址上限到 ZB 量级（2^64 × 512 字节 ≈ 9.4 ZB）；默认可建 128 个分区；每个分区有类型 GUID（标识这是什么分区）和唯一 GUID（标识具体哪一个）；分区表有 CRC 校验且在磁盘末尾留一份备份。MBR 的 2.2TB 死线和 4 分区限制同时解除。
- **固件认识文件系统，引导程序是文件不是扇区**：UEFI 规定了一块 ESP（EFI System Partition，EFI 系统分区，FAT32 格式），固件内置 FAT 驱动，能按路径加载文件：Windows 的引导程序就是 ESP 上的文件 `\EFI\Microsoft\Boot\bootmgfw.efi`。"446 字节接力赛"就此作废——引导程序可以写得任意大、任意复杂，第一行代码就能读文件。
- **真正的驱动模型与协议数据库**：UEFI 驱动也是 .efi 模块，可放在固件里、扩展卡上或 ESP 上，按需加载。驱动之间不直接调用，而是通过 Protocol（协议：一组以 GUID 为键注册的函数表，思想类似 COM 的接口）互相提供服务——比如磁盘 I/O 协议、图形输出协议、网络协议。这意味着新硬件的支持是"插一个驱动模块"，而不是"改固件本体"。Option ROM 的无政府状态到此终结。
- **启动菜单变成 NVRAM 变量**：启动项、启动顺序存放在主板 NVRAM（非易失存储）里的 UEFI 变量中，如 BootOrder、Boot0001 等，每项指向某个 ESP 文件。操作系统安装程序通过运行时的变量服务写这些条目（Linux 的 efibootmgr、Windows 的 bcdedit 底层改的就是它们）。双系统切换、改启动顺序不再是改扇区，而是改数据。
- **服务分两班，交接有一刀切**：Boot Services（启动服务）只在移交前有效：内存分配、映像加载、协议查询、事件定时器，一应俱全，引导程序在这段时间等于跑在一个小型操作系统上。引导程序调用 ExitBootServices() 是那一刀：此后启动服务全部作废，内存归操作系统。而 Runtime Services（运行时服务）终身有效：读/写 UEFI 变量、读硬件时钟、系统重置、固件更新胶囊（Capsule，见下条）——操作系统运行时还能通过它们摸到固件留下的这几只手。
- **Secure Boot 有了安放点**：既然引导程序是文件、加载动作归固件管，验签就能插在加载前：固件按 PK / KEK / db / dbx 四级密钥库校验每个 .efi 的签名，签不过不执行。这套四级链的细节在《PatchGuard 攻防史》的 HVCI/Secure Boot 详解里已经讲透，这里只点明它与 UEFI 的关系：**Secure Boot 是 UEFI 规范的一部分，不是外挂**；EfiGuard 之所以必须先关 Secure Boot，也是因为它要在这一层动手。反过来说，BIOS 世界不是"没做验签"，是接口上根本没有验签的位置。
- **固件更新标准化**：Capsule Update（胶囊更新）让操作系统在运行时把一段签名过的固件更新包交给固件，重启时由固件自己验签并刷写。Windows Update 能给主板推固件更新，走的就是这条路；BIOS 时代刷固件要靠各厂商私有 DOS 工具。
- **网络与图形是标配协议**：固件自带 TCP/IP 栈，PXE 网络启动、HTTP Boot（UEFI 2.5 起，直接从 HTTP 服务器拉引导文件）都是标准能力；图形输出协议 GOP 取代了实模式 int 10h，启动期就能有高分辨率图形界面和鼠标。

内部再分一层（EDK II 的 PI 规范，跟内核初始化的阶段划分可以对位）：SEC（上电、临时内存）→ PEI（内存控制器初始化，主内存没起来之前只能拿 CPU 缓存当 RAM 用）→ DXE（驱动分发主阶段，绝大多数驱动与协议在这里装载）→ BDS（按 BootOrder 选启动项）→ 操作系统接管后进入 RT（运行时）。分阶段的病根和 WRK 里内核分阶段初始化是同一个道理：下一步依赖的东西（比如堆）要靠上一步先造出来。

**和 ACPI 的分工**（顺带钉死一个常混的点）：ACPI（Advanced Configuration and Power Interface，高级配置与电源接口）是另一套规范，管硬件拓扑描述（各种描述表）和电源管理（睡眠状态、风扇、电池）。它和 UEFI 通常同住在一块主板的固件里，但分工不同：**UEFI 管"怎么把系统启动起来并移交"，ACPI 管"系统跑起来后怎么描述和管理硬件电源"**。操作系统从 UEFI 手里接过启动，从 ACPI 表里读硬件地图。

**代价：讲透也要讲另一面**

UEFI 不是没有代价的。固件从一段几十 KB 的汇编变成了带驱动模型、网络栈、文件系统的小型操作系统，DXE 驱动动辄上百个，代码量和攻击面同步膨胀：LoJax（2018）是第一个被发现的野外 UEFI rootkit，BlackLotus（2023）能绕过 Secure Boot——攻击者把战场推进到了操作系统之下、杀毒软件和重装系统都够不着的那一层，这和攻防史上"每次反制把战场推向更外围"的规律是同一条线。各厂商实现质量参差、闭源、难调试也是实账。但回头路不存在：2.2TB 死线和实模式起点是物理性的，BIOS 没有任何修补路径能绕过去。

最后和 Windows 学习线对位收束：WRK 的世界是 BIOS + MBR + ntldr + boot.ini，内核接手时机器状态是引导链层层跳板攒出来的；现代 Windows 的世界是 UEFI + GPT + bootmgfw.efi + winload.efi，内核接手前启动服务已被 ExitBootServices 一刀切断、只剩运行时变量服务可用。中间隔着的，正是这一整套接口革命。
