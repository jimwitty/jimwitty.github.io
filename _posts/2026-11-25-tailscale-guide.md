## 一句话说清

Tailscale 是一款基于 WireGuard 的组网工具。它让你手里的每一台设备——家里的服务器、笔记本、手机、云上的 VPS——不管身处哪个网络、有没有公网 IP，都像接在同一台交换机上一样互相直连，互相用一个固定的私有 IP 地址访问。

装好之后，你在外面用手机打开 `http://100.x.y.z:22`，连的就是家里那台服务器；从服务器上直接 `ssh` 另一台设备的内网地址，用的也是这条加密通道。不用在路由器上开端口，不用记动态域名，不用搭一台中心 VPN 服务器。

免费的个人版足够个人和家庭使用：最多 6 个用户，设备数量不限。

## 它解决的是什么问题

要理解 Tailscale 先解决什么，得先看没有它的时候，远程访问一台家里设备有多麻烦。

### 家里没有公网 IP

今天大多数家庭宽带都没有公网 IP。运营商把一整个小区的用户都塞进同一个地址段后面，这叫 CGNAT（运营商级 NAT）。你的路由器拿到的是一个内网地址，外面根本找不到你。想从外面连回家里的服务器，路由器端口转发这条路从一开始就不存在——因为外面连你的路由器都连不上。

### 有公网 IP 也麻烦

就算有公网 IP，端口转发也是一件脏活：登录路由器配规则、IP 一变规则就失效、每个服务开一个端口、每个端口都暴露在全网扫描之下。SSH 的 22 端口一旦暴露，爆破日志几天就能涨到几万条。公网 IP 本身还经常变，动态域名又得多挂一个服务。

### 传统 VPN 也不省心

自己搭 OpenVPN 或 WireGuard，等于在家里或云上养一台中心服务器：装软件、配证书、管密钥、分发配置、处理 NAT 穿透、服务器一挂全网断。WireGuard 本身已经很简单了，但它只解决"两台机器之间怎么加密通信"，不管"一百台机器之间怎么互相发现、怎么换密钥、谁有资格加入"。这些脏活才是真正耗人的部分。

Tailscale 做的事情，就是把 WireGuard 底下这些脏活全包了：密钥分发、身份认证、节点发现、NAT 穿透、DNS、访问控制。它只留给你两件事：装客户端，登录账号。

## 它是怎么工作的

Tailscale 的架构可以拆成三块：数据面、控制面和中继。理解这三块，就理解了它几乎全部的行为。

### 数据面：WireGuard，加密的底座

设备与设备之间的流量，走的是 WireGuard 协议。

WireGuard 由独立安全研究员 Jason A. Donenfeld（网名 zx2c4）创造。2015 年他动手写第一版，2017 年 2 月在 NDSS（网络与分布式系统安全研讨会）上发表论文《WireGuard: Next Generation Kernel Network Tunnel》，设计从一开始就经过同行评审。2020 年 1 月 28 日，Linus Torvalds 合并了网络子系统的更新，WireGuard 进入 Linux 主线；2020 年 3 月 29 日随 Linux 5.6 正式发布，此后每一台装有 5.6 及以上内核的 Linux 机器都自带 WireGuard。

它出名的原因是简单和快。OpenVPN 加 IPsec 的代码量以十万行计，WireGuard 的核心实现大约只有 4000 行，少到一个人能读完并审计完。加密套件也只有一个固定组合：ChaCha20-Poly1305 做加密、Curve25519 做密钥交换、BLAKE2s 做哈希、Noise 协议框架做握手——没有算法协商，就没有协商出错的空间。

WireGuard 还有一个关键设计叫"密钥路由"（cryptokey routing）：一个公钥对应一个允许访问的 IP 段，收到的数据包必须能用某个已知的公钥解密才放行，解密失败直接丢弃。这意味着一台 WireGuard 节点对没有密钥的人是"隐身"的：它不会回任何错误，不会暴露自己在监听，扫描器扫过去就像那台机器不存在一样。

Tailscale 的每一台设备都是一台 WireGuard 节点。设备之间直连时，流量就是标准的 WireGuard 加密隧道，不经过任何第三方服务器。

### 控制面：协调服务器，只管"谁在哪"，不管流量

WireGuard 有个短板：它不管节点怎么互相找到对方、怎么交换公钥、怎么知道谁有资格加入。两台机器要建隧道，得先有人把一方的公钥和地址告诉另一方。

Tailscale 的协调服务器（coordination server）就是干这个的。它只做三件事：

1. **身份**：你用已有的账号登录——Google、Microsoft、GitHub、Apple 等——协调服务器认这个身份，不自己再造一套密码体系。
2. **发地址**：每台加入的设备分到一个 `100.64.0.0/10` 段内的固定私有地址，比如 `100.114.62.88`。这个段是 RFC 6598 规定的 CGNAT 保留段，专门留给运营商级 NAT 用，正常情况下不会和你家里的 `192.168.x.x`、公司的 `10.x.x.x` 冲突。
3. **发地图**：它把全网的节点清单（netmap）推给每一台设备：谁在线、公钥是什么、公网地址和端口是什么。设备拿到地图之后，自己去找对方建隧道。

关键点：协调服务器只分发元数据，**流量不经过它**。你的文件、SSH 会话、视频流，只在两台设备之间流动。Tailscale 官方也看不到你的流量内容——加密密钥只存在于两端设备上。

### 中继：DERP，打不通时的兜底

两台设备都在 NAT 后面时，建直连需要"打洞"：双方同时向对方的公网地址和端口发包，让各自的 NAT 设备以为这是对已发出去的请求的回包，从而放行。锥形 NAT 下这招通常一次就通；对称型 NAT 或运营商 CGNAT 下，打洞常常失败。

打洞失败时，流量走 DERP 中继。DERP 是"Designated Encrypted Relay for Packets"（指定加密包中继）的缩写，是 Tailscale 在全球部署的一批中继服务器。设备连不上对方时，自动把加密包发给最近的 DERP 节点，由它转发给对方。DERP 只看得到加密包和元数据（谁在和谁说话、包有多大），看不到内容——因为包在离开设备之前就已经用 WireGuard 加密过了。

所以准确的说法是：**协调服务器是介绍人，DERP 是兜底中继，都不是必经的代理**。直连能通时流量只走直连；直连通不了才走中继，代价是多一跳延迟和带宽上限。

### 信任模型：三档，分开看

作为安全工具，Tailscale 的信任关系要分三档说清楚，不能混成一句"信不信任 Tailscale"：

- **流量内容只信任两端**：加密密钥只在设备上，协调服务器和 DERP 都看不到明文。这是 WireGuard 保证的，不是口头承诺。
- **元数据归 Tailscale**：协调服务器知道你的设备清单、在线状态、IP 地址；DERP 知道谁在和谁通信。元数据本身就是服务的一部分，无法既用托管控制面又不给它。
- **控制面是信任根**：协调服务器有权决定谁能加入你的网络、给谁发密钥。它的账号一旦被盗，攻击者能把自己的设备加进你的网。所以账号本身的安全（强密码、双因素认证）就是整个网络的安全底线。想要去掉这个信任根，可以自搭 Headscale（开源的第三方控制面实现），代价是自己运维。

## Tailscale 公司小传

理解一个工具，有时要先理解做它的人为什么要做它。

Tailscale Inc. 是一家 2019 年成立于加拿大多伦多的公司，创始人是 Avery Pennarun、David Crawshaw 和 David Carney，三人此前都在谷歌共事，Pennarun 和 Carney 在 Google Fiber（谷歌的光纤宽带业务）担任工程管理职务，团队还在 Fuchsia 操作系统上做过网络方面的工作。Brad Fitzpatrick 于 2020 年 1 月离开谷歌后不久加入，成为第四位联合创始人。

Brad Fitzpatrick 这个名字在互联网历史上分量很重：他早年创建了 LiveJournal（博客社区先驱），发明了 Memcached（支撑起 Facebook、Twitter、维基百科的缓存系统），参与创建了 OpenID，之后在谷歌 Go 语言团队工作十多年。Tailscale 的客户端正是用 Go 写的。

公司的名字来自谷歌 2013 年的一篇著名研究论文《The Tail at Scale》（规模下的长尾），讲的是大规模系统里极少数慢请求如何拖垮整体延迟。创始团队的出发点是：大多数软件团队做的内部工具根本不需要大规模扩展，却仍然要为联网和访问控制付出不成比例的代价。WireGuard 给了他们一条快速简单的加密隧道，但缺一个控制面来管密钥、身份和 NAT 穿透，Tailscale 就是补上这一层的产品。

时间线：2019 年成立，2020 年 4 月正式推出并开放使用，同年 11 月拿到 Accel 领投的 1200 万美元 A 轮；2022 年 5 月拿到 CRV 和 Insight Partners 领投的 1 亿美元 B 轮；2025 年 4 月拿到 Accel 领投的 1.6 亿美元 C 轮。公司从一开始就是全员远程办公。

## 和同类方案比，它赢在哪、输在哪

### 对比传统 VPN（OpenVPN / IPsec）

传统 VPN 是"中心辐射"型：所有设备先连到一台中心服务器，再由它转发。优点是模型简单、控制集中；缺点是中心服务器既是单点故障，又是性能瓶颈，异地设备之间通信要绕路。Tailscale 是网状（mesh）：设备之间能直连就直连，中心只负责介绍，不转发流量。设备越多、分布越散，网状的优势越大。

### 对比手动 WireGuard

手动 WireGuard 和 Tailscale 的数据面是同一个协议，区别全在控制面。手动方案每加一台设备就要手工交换公钥、改配置、重启服务，十台以上就是负担；Tailscale 上装客户端登录即完成。手动方案的好处是零托管、零信任第三方，坏处是所有脏活自己干。设备少、网络固定、愿意自己维护的，手动 WireGuard 更纯粹；设备多、经常换地方、想省事的，Tailscale 更合适。

### 对比端口转发和内网穿透（frp、ngrok）

端口转发和 frp 这类工具解决的是"把内网服务暴露到公网"：开一个口子，让全世界都能敲门，安全靠服务自身的密码和补丁。Tailscale 解决的是"让自己的设备互相访问"：不开任何公网口子，访问者必须先是网里的设备、拿着有效的身份和密钥。前者是"对外营业"，后者是"对内串门"，用途不同。只想自己远程连回家里的机器，Tailscale 是更收敛的选择。

### 对比 ZeroTier、Netbird

ZeroTier 是另一款老牌组网工具，同样做虚拟局域网和 NAT 穿透，免费版设备数更宽松，控制器也可以自搭。Netbird 则是全开源的同类产品，控制面和管理后台都能自己托管。Tailscale 的优势在于客户端成熟度、平台覆盖和文档质量，劣势是控制面闭源。注重自托管和开源血统的，可以看看 Netbird 和 Headscale；注重开箱即用的，Tailscale 仍是第一选择。

## 上手：注册、安装、进网

### 第一步：注册账号

打开 [tailscale.com](https://tailscale.com)，点 Sign Up，用已有的账号登录：Google、Microsoft、GitHub、Apple 等都可以。Tailscale 自己不存你的密码，身份交给这些服务商验证。免费的个人版（Personal）不需要信用卡。

注册完你就拥有了一个 tailnet（Tailscale 对"你的私人网络"的叫法）。刚开始里面只有你一个人、一台设备也没有。

### 第二步：给每台设备装客户端

客户端覆盖几乎所有平台：

- **Linux**：各发行版有官方仓库，装完 `tailscale` 命令就绪。无图形界面的服务器也一样装，登录方式见下一步。
- **Windows / macOS**：官网下载安装包，装完在任务栏或菜单栏点登录。
- **Android / iOS**：应用商店搜索 Tailscale 安装。
- **路由器 / NAS**：群晖、威联通、OpenWrt、pfSense、OPNsense 都有官方或社区客户端，适合把整段内网接进来。

### 第三步：登录进网

有图形界面的设备，打开客户端点登录，浏览器里点一下授权，设备就进网了，自动拿到一个 `100.x.y.z` 的固定地址。

无图形界面的服务器（比如一台最小安装的 Linux 服务器）登录时没有浏览器可点，终端里跑 `sudo tailscale up`，它会打印出一条 `https://login.tailscale.com/a/xxxx` 这样的链接。把这条链接复制到手机或电脑的浏览器里打开，登录同一个账号点授权，服务器就进网了。链接有效期 5 天。

### 第四步：验证连通

在任意一台设备上跑 `tailscale status`，能看到全网设备清单、各自的 IP 和在线状态。从一台设备 `ping` 另一台的 `100.x.y.z` 地址，通了就是直连成功。`tailscale ping <IP>` 还会告诉你这条路是直连还是走了 DERP 中继。

## 无人值守进网：auth key

上面的登录方式需要人在浏览器里点一下授权。给服务器批量进网、或者服务器没有人守着时，用 auth key（认证密钥）更合适。

在管理台的 Settings → Keys 里点 Generate auth key，生成时有几个选项：

- **Reusable（可复用）**：勾上，一把密钥可以给多台设备用；不勾，一次性的，用过即废。
- **Pre-authorized（预授权）**：勾上，用这把密钥进网的设备直接获得批准，不用管理员再点一次；不勾，设备进网后停在"待批准"状态，等人去管理台点批准。
- **Ephemeral（临时节点）**：给短期存在的设备用，断线后自动从网络里删除。服务器不要勾。
- **有效期**：默认 90 天，密钥过期只影响"用它进网"这件事，已经进网的设备不受影响。

密钥形如 `tskey-auth-xxxx`，只显示一次。生成后在服务器终端跑：

```bash
sudo tailscale up --authkey=tskey-auth-xxxx --hostname=rocky9
```

`--hostname` 是给这台设备起个在网里的名字，之后可以用名字代替 IP 访问。整条命令跑完，设备直接进网，全程不需要浏览器。

auth key 等同于密码：谁拿到它，谁就能往你的网络里加设备。不要贴在聊天记录、脚本或公开仓库里。用完之后可以在管理台吊销它，已经进网的设备不受影响。

## 常用功能

### MagicDNS：用名字代替 IP

Tailscale 内置的 MagicDNS 会给每台设备一个域名，比如 `rocky9.tailxxxxxx.ts.net`，在网内任何设备上直接用这个域名就能访问，不用记 `100.x.y.z`。在管理台 DNS 设置里可以开启或关闭，也可以把自己已有的域名指过来。

### 设备批准（device approval）

新设备进网后，管理员可以在管理台里批准或拒绝。默认情况下，用同一个账号登录的设备自动获得批准；当 tailnet 开启了"设备批准"要求、或设备是用未预授权的 auth key 加入时，才会停在待批准状态。批准也可以走 API 完成，不用打开管理台。

### 节点密钥过期

每台设备的节点密钥默认 180 天过期。过期后设备断连，但不会从设备列表里消失，重新认证就能回来。长期在线的服务器建议关掉密钥过期：在管理台 Machines 里点进设备，选 Disable key expiry；或者在设备本机跑：

```bash
sudo tailscale set --key-expiry=off
```

### 子网路由：把一整段内网接进来

家里或办公室还有一整段 `192.168.1.0/24` 的内网，里面有打印机、摄像头、不方便装客户端的设备，可以让网里的一台设备当"子网路由器"：它在自己终端上声明要转发的网段，管理员在管理台批准这条路由，此后网内任何设备访问 `192.168.1.x` 都会经由它中转。等于用一台设备把整个内网搬进了 tailnet。

### 出口节点：借道出网

指定网里的一台设备当出口节点（exit node），其他设备可以把全部上网流量经由它出去：出门在外连公共 Wi-Fi 时流量先加密回家里再出网，或者让一台设备的出口 IP 变成另一台的。手机客户端里点一下就能切换。Tailscale 还提供 Mullvad 合作的出口节点，可以直接借用 Mullvad 的 VPN 出口。

### Tailscale SSH：不用管密钥的 SSH

在管理台开启 Tailscale SSH 后，网内设备之间用 `ssh user@hostname` 就能登录，认证走 Tailscale 的身份体系，不用再往每台机器上分发 SSH 公钥，还能在访问控制里按用户、按设备写"谁能连谁的 22 端口"。对管理多台服务器的人来说，这是最省事的 SSH 方案之一。

### 访问控制（ACL）

默认的访问控制策略是"网内所有设备互相都能访问"。想收紧时，在管理台的 Access controls 里写规则：比如只允许手机访问家里的 NAS，不允许它碰服务器的 SSH 端口；或者只允许某个用户访问某台设备。规则用 HuJSON（一种带注释的 JSON）写，改完实时生效，不用重启任何设备。

### 免费版之外的功能

Taildrive（在网内设备之间共享文件夹）、Tailscale Funnel（把本地服务通过 `https://xxx.ts.net` 临时暴露到公网）、文件传输（`tailscale file cp` 在设备间传文件）等，都是在同一个网络底座上长出来的小功能，有需要时再逐个了解，不必一次全学会。

## 常见问题与边界

### 免费版的"用户"是什么意思

这里的"用户"指的是人（一个身份），不是设备。免费的个人版允许一个 tailnet 里最多有 6 个用户：你自己是其中一个，还可以再邀请 5 个人加入。被邀请的人用自己的账号（Google、Microsoft 等）登录，他们的设备就会出现在同一个 tailnet 里，和你的设备互相可见，访问权限由 ACL 规则控制。

一个人可以拥有很多台设备：你的笔记本、手机、服务器都算在你这一个"用户"名下。设备数量在免费版里是不限的（"Unlimited user devices"），以前的 100 台上限已经在 2026 年 4 月的定价调整中取消了。

### 直连还是中继，怎么看

`tailscale ping <对方IP>` 的输出会写明路径。显示 `direct` 加一串公网地址和端口，就是直连；显示 `via DERP` 加某个城市名，就是走了中继。直连通常延迟更低、带宽更高；走中继也能用，只是多一跳。如果长期走中继且延迟敏感，先查两端是不是都在对称型 NAT 或 CGNAT 后面，再考虑换网络环境。

### 速度有多快

直连时速度取决于两端之间的真实网络，和 Tailscale 本身关系不大；WireGuard 的加密开销在现代 CPU 上几乎可以忽略。中继时速度受 DERP 节点带宽限制，日常 SSH、传文件、看监控都够用，跨国大文件传输会慢一些。

### 一台设备能加几个网络

一台设备一次只能加入一个 tailnet。想切换网络，先 `tailscale down` 退出，再用另一个账号登录。多网络并行的需求，得用多台设备或者虚拟机来分。

### UDP 被禁用的环境怎么办

WireGuard 的打洞和隧道都走 UDP。如果设备所在的网络完全禁了 UDP 出站（某些沙箱、受限容器环境就是这样），Tailscale 客户端连协调服务器仍可通过 TCP 完成，但设备之间既打不了洞、也建不起 UDP 隧道，实际连通性会受影响。这种环境不适合做 Tailscale 节点，控制面能连上不等于数据面能通。

### 账号被盗会怎样

前面说过，控制面是信任根。能登录你的 Tailscale 账号的人，就能往你的网络里加设备、改访问策略。所以这个账号务必开双因素认证，密码不要复用。企业版还有 tailnet lock（用节点密钥签名做二次确认）等加固手段。

### 不想把控制面交给别人

Headscale 是开源社区实现的第三方控制面，兼容 Tailscale 客户端，可以自己部署在服务器上。代价是自己运维：升级、备份、高可用都得自己管。个人使用且信任 Tailscale 官方服务时，没必要折腾；对控制面有合规或主权要求的，再考虑这条路。

### API 能做什么

Tailscale 提供 REST API（`https://api.tailscale.com/api/v2/`），用 API access token 认证，能做的事基本等同于管理台：列设备、批准设备、开关密钥过期、生成和吊销 auth key、改 ACL、配 DNS。适合把"新服务器进网"做成自动化：生成一把预授权的 auth key 发给新机器，机器跑一条命令进网，之后再调接口把它的密钥过期关掉，全程不用打开浏览器。

## 小结

Tailscale 的本质，是把 WireGuard 从"两个人之间的加密隧道"升级成"一群设备之间的私人网络"，升级的办法是补上一个轻量的控制面：管身份、发地址、发地图，打不通时给个中继兜底。它不替你做访问控制的决策，也不碰你的流量内容——这两件事分别留给了 ACL 和 WireGuard 的端到端加密。

对个人用户来说，它的价值可以用一句话概括：**不用公网 IP，不开端口，不养中心服务器，就能让所有设备像在同一间屋子里一样互相访问**。免费版 6 用户、设备不限量的额度，对个人和家庭绰绰有余。先从两台设备开始，装上、登录、ping 通，再慢慢把服务器、NAS、手机一台一台加进来，网络就是这样长起来的。
